# 多客户制作与版本隔离

仅在用户处理多位客户或多单任务时使用。本 Skill 本身不是后台接单平台，不提供自动收费、无人值守队列或跨平台无限批量运行。

## 每单最少信息

每只宠物至少有 1 张可用照片；正面/三分之二侧脸能看清五官即可开始，清晰补充照有帮助但不强制三张。需要合照时明确几只、各自对应哪些图片，以及是否采用一大一小贴贴款。输出数量不明用 1 张。

可用 [订单简表](../templates/order-brief.md)。不要把一张长问卷强加给只想按同款出图的客户。

## 隔离原则

每个客户使用一个独立文件夹或独立对话。新订单清空上一订单的身份图、宠物特征、选中作品和编辑底图，只沿用通用风格规范。

风格目录保持只读，不把客户原照和成图偷偷加入公共模板。不要因上一单是黄眼蓝猫，让下一单也默认黄眼。不能把客户图片上传到未授权图库、公开仓库或公开作品集。

## 可用文件环境的目录

```text
pet-orders/
  order-001/
    brief.md
    state.yaml
    originals/              # 本单原照，只读保存
    prompts/                # 本单实际用过的语义提示
    candidates/             # 单宠或合照候选
    edits/                  # 明确指向父版本的定向修改
    delivery/               # 用户选中的交付版
```

这些是建议目录，不代表已在用户机器上创建。不要把订单数据写进已安装的 Skill 目录。

## 最短生产路线

单宠：读原照与风格 → 锁定特征 → 生成 → 视觉检查 → 交付。

合照：读本单两组身份图或已有单宠作品 → 按所选布局生成/编辑 → 检查接触与结构 → 交付。

修改：锁定真实底图 → 写明改动项与保持项 → 定向编辑 → 对比检查 → 交付。

任务已要求多单时，在当前会话中按单推进，不把多个客户的照片混合进同一次生成。没有常驻执行工具就不承诺离线后继续生产。每单生成次数与额外收费接口遵守用户授权，不无条件预生成多个版本。

## 版本命名

可用 `order-001_cat_p1_v01.png`、`order-001_duo_v01.png`、`order-001_duo_v02_fur-soft.png`。扩展名必须符合实际文件格式；工具返回 WebP 时不要仅改名假装 PNG。

`latest_candidate` 指最新真实产物；`last_approved` 只在用户明确选中后更新。修改失败仍保留父版本，不覆盖原照和已经交付的成品。

## 新风格反馈

“这张更软”“这次猫再小一点”默认只是本单局部修改，不自动更改所有未来订单的全局标准。用户明确说“以后都这样”时，再更新风格配置和版本说明。注意不要改写其他客户已经确认的作品。
